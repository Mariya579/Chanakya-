# Existing HTML launch and command validation — 25 October 2026

The reported task was `run that file`, referring to the styled `public/index.html`. Its activity showed dependency installation followed by `npm start` in `public`, although that folder's package.json only contained dependencies and had no start script. The agent then repeatedly proposed completion. The final generic validation message concealed the useful `npm error Missing script: "start"` output.

This update adds `preview.start`, an approved, owned localhost preview for plain HTML. It needs project-command permission, but no package download, Python or npm installation. Entry-file versions bind to approval. Static assets use the existing native guarded file reads, within the HTML file's directory. Protected files, traversal, changed workspace roots, links and unsupported asset types are refused. Previews bind to 127.0.0.1 on a free port and use a random URL prefix; cross-origin reads are refused. Guarded assets retain the existing 1 MiB per-file limit. A successful preview must return HTTP 200 for its entry before it is reported ready. Owned Stop, cancellation, grant revocation and backend exit close it.

For an unambiguous launch-only follow-up such as `run that file`, the service resolves the latest source from its owned conversation and prepares the appropriate preview/run action directly through exact approval. It does not ask the model to invent npm commands. Missing npm scripts are diagnosed before launching a process; declared dev/start scripts and npm's server.js fallback remain supported. More complex tasks can also request an HTML preview through the model tool catalog or the service's missing-command recovery.

The Run panel now has **Preview HTML** for a selected or recently changed HTML file. Its localhost URL and Stop controls use the existing owned-job UI. Failed checks retain their actual command, exit status and useful stderr, instead of replacing that evidence with a generic completion warning. Requested Python/Node syntax commands are classified as syntax checks, preserving fresh-source validation requirements.
